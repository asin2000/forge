## 3. Cloud Run deployment (HUM-1 surface behind IAM)

`gcloud run deploy forge-dashboard --source . --service-account
forge-dashboard@... --no-allow-unauthenticated` →
`https://forge-dashboard-720097217888.us-central1.run.app`
(revisions 00001-rpv, then 00002-966 after the auth finding below).

**Production finding (revision 00001)**: Cloud Run's IAM layer verifies the
caller's Google-signed ID token and then forwards it with the signature
STRIPPED. In-container re-verification therefore fails structurally:

```
google.auth.exceptions.MalformedError: Could not verify token signature.
  File "/app/services/dashboard/auth.py", line 28, in _google_verify
```

…and the unhandled verifier exception surfaced as HTTP 500. Fixes (revision
00002): (a) ANY verifier failure maps to PermissionError → 401, never 500;
(b) behind Cloud Run IAM the deploy sets `TRUST_PLATFORM_AUTH=1` and the
app reads the platform-validated token's claims (issuer, verified email,
expiry still enforced) — safe only because `--no-allow-unauthenticated`
means no request reaches the container without platform verification.
Unit-covered (3 new tests) including the flag-off path.
